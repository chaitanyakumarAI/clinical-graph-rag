Verdict: query rewriting does what it was built for: it repairs retrieval for messy, abbreviated questions. It is neutral on questions that are already well written. Across the 12 answerable questions, context recall rose from 0.97 to 1.00 and answer correctness was flat (0.76 → 0.75). On the 5 messy questions, recall rose from 0.93 to 1.00 and correctness from 0.79 to 0.84. These differences are small compared with the judge noise measured below, so treat them as directional rather than proven.

1. Rewriting fixes retrieval for messy questions

  • Q4 "side efects of metformn?" was rewritten to "What are the side effects of metformin?". Context recall went from 0.67 to 1.00: the typo-free query found the metformin passage the literal query missed.
  • Q10 "T2DM pt w/ albuminuria needs a BP drug…" was expanded and split into 2 sub-queries. The extra search brought in the diabetes guide, and correctness went from 0.76 to 0.87.
  • Q2 "why is high BP called silent": correctness went from 0.54 to 0.70.

2. No benefit on clean questions, and some measured noise

For 6 of the 7 clean questions the rewriter returned the question essentially unchanged (it only split Q8), so retrieval was identical. Q12 calibrates the noise: its rewritten query was word-for-word the original, retrieval returned the same documents, and both answers say the same thing, yet answer correctness was judged 0.72 in one run and 0.46 in the other. Differences of roughly ±0.25 on a single question are therefore judge and generation variance, not an effect of rewriting.

3. Retrieval is not the bottleneck; answer synthesis is

Context recall is close to 1.0 and faithfulness is 0.92–0.94 in both configurations, but answer correctness stays around 0.75. The missing points come from the answer step:

  • Answers are too brief. Q11 correctly names amiodarone and CYP2C9 but omits the "reduce the warfarin dose by 30–50%" advice, although that sentence was in the retrieved context. The generator prompt's "be concise" rule costs completeness.
  • Cross-document reasoning is the weakest area (multi-hop correctness about 0.65–0.72). Q8, "Which diabetes drugs interact with blood-pressure medications?", misses the insulin/glipizide + metoprolol interaction in both configurations. Answering it requires knowing that insulin is a diabetes drug (diabetes guide) and metoprolol a blood-pressure drug (hypertension guide). In the rewrite run the model also asserted that no other diabetes drug interacts, which is wrong.
  • Over-generalisation lowers faithfulness. In Q12 both runs claimed that lisinopril + hydrochlorothiazide alone can cause acute kidney injury. The documents only state this when an NSAID is added (the "triple whammy").

4. Grounded refusal works

Q13 (atorvastatin dose, not in the documents) was correctly answered "Insufficient information in the provided sources" in both runs. RAGAS scores any refusal 0 for relevancy and recall by design, so Q13 is excluded from the averages.

5. Cost of rewriting

One extra LLM call per question (about 1 second of model time on Groq). Median end-to-end latency rose from 60 s to 78 s. Almost all of that is the client-side rate limiter waiting, because the extra call spends part of the free tier's 8,000 tokens/minute budget. On a paid tier the overhead would be about a second.

6. Issues found and fixed during the evaluation

  • The reranker crashed on every query (FlagEmbedding is incompatible with transformers 5), so every candidate received the same fallback score and graph paths always outranked document text. Before the fix, a test query had 0 of 8 context slots filled with document chunks. It now runs through sentence-transformers' CrossEncoder.
  • Leftover data from earlier uploads (sample.pdf, sample2.pdf and an orphaned source tmp880ca9_x with no registered document) appears in most results and dilutes the context.

Recommendations (in order of expected impact)

  1. Improve the answer prompt: ask for every clinically relevant fact in the context that answers the question (mechanism, consequence, management), and forbid generalising beyond what a passage states.
  2. Strengthen cross-document graph retrieval: for "which X drugs interact with Y drugs" questions, traverse (drug)-[:TREATS]->(disease) together with (drug)-[:INTERACTS_WITH]-(other drug), so drug-class membership from one PDF links to interactions from another.
  3. Keep rewriting on. It is cheap and protects against messy input. To save the extra call, it could be merged into the query-planner call, which already reads the question.
  4. Clean the database of legacy and orphaned chunks, then re-run this evaluation.
  5. Evaluate at a larger scale: 30 or more questions and 3 repeated runs, averaging scores, to get below the ±0.25 per-question noise.
